02 / Projects

Case studies

Four projects spanning the same loop from a different angle each time: sense something in the physical world, decide, then act — in software, in hardware, or both.

01
Computer Vision

Computer Vision Virtual Controller

A real-time hand-tracking interface that lets a webcam replace a mouse — built for touchless control without any extra hardware.

Problem

Physical input devices break down the moment hands are occupied, dirty, or out of reach — a webcam is already there and unused.

Approach

MediaPipe tracks 21 hand landmarks per frame; OpenCV handles the video pipeline; landmark positions are mapped to screen coordinates and smoothed to cut jitter before PyAutoGUI drives the OS cursor.

Result

A working touchless controller with pinch-to-click gesture recognition, running in real time on consumer webcam hardware.

PythonOpenCVMediaPipePyAutoGUI
02
Embedded Safety

Automated Gas Detection & Mitigation

A standalone safety system that detects hazardous gas concentration and responds without waiting on a human — or a network connection.

Problem

Gas leaks need a response measured in seconds, not in however long it takes someone to notice and react.

Approach

An MQ-135 sensor's digital alert output is wired directly into Arduino digital pin 2, so a threshold breach is read the instant it happens. The firmware then writes a status update to an LCD and switches on a DC fan to ventilate the space.

Result

A closed-loop detect-and-mitigate cycle that runs entirely on the microcontroller — no cloud, no app, no dependency to fail.

ArduinoEmbedded C++MQ-135LCDCircuit Design
03
Software Architecture

MathEngine CLI

A command-line file processor built to prove out a clean OOP architecture for data work, not just to get one answer out of one file.

Problem

Ad-hoc scripts for reading, computing, and logging data get tangled fast and don't survive a second use case.

Approach

Object-oriented design separates file reading, math computation, and logging into independent classes behind a single CLI entry point, so any one piece can change without touching the others.

Result

A reusable processor where swapping a data source or an output format is a one-class change, not a rewrite.

PythonOOPCLIPandas
04
Hardware Security

Embedded Hardware Security Lab

An ongoing exploration of firmware and hardware-level security — the layer below the app, where most security guidance stops applying.

Problem

Embedded devices trust their communication protocols and firmware by default, which is exactly where they're least tested.

Approach

Hands-on testing of hardware communication protocols and firmware behavior to understand how embedded systems fail — and where they should be hardened.

Result

A growing set of protocol notes and firmware test cases that now inform how I design every other embedded project on this page.
